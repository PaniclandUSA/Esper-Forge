# Contributing to ESPER-FORGE

Thank you for your interest in contributing to ESPER-FORGE. This project aims to provide mathematical certification of semantic integrity for AI systems, with primary focus on literacy liberation and epistemic restoration.

## Mission Alignment

Before contributing, please ensure your work aligns with:

1. **Human dignity preservation** - All features must honor individual truth and agency
2. **Mathematical rigor** - Claims must be provable, not aspirational
3. **Epistemic honesty** - Uncertainty must be preserved, not collapsed
4. **Open accessibility** - Work must remain freely available

## Ways to Contribute

### 1. Code Contributions

**Areas needing development**:
- Operator implementations (see `src/operators/`)
- Validation algorithms (see `src/validators/`)
- Certificate generation (see `src/core/certificates.py`)
- Test coverage (see `tests/`)

**Process**:
1. Fork the repository
2. Create a feature branch (`git checkout -b feature/your-feature`)
3. Write tests first (TDD approach)
4. Implement feature
5. Ensure all tests pass
6. Submit pull request with clear description

**Code standards**:
- Python 3.10+
- Type hints required
- Docstrings (Google style)
- Black formatting
- pytest for testing

### 2. Documentation Contributions

**Areas needing documentation**:
- Mathematical proofs (see `docs/03-ENTANGLEMENT-OPERATORS.md`)
- Use case examples (see `examples/`)
- Deployment guides (see `docs/08-DEPLOYMENT.md`)
- Translation to other languages

**Process**:
1. Check existing documentation structure in `docs/`
2. Follow markdown style guide
3. Include diagrams where helpful (use Mermaid)
4. Submit PR with clear rationale

### 3. Research Contributions

**Areas needing research**:
- Decoherence field models
- Correlation tensor mathematics
- Closure condition proofs
- Comparative analysis with existing systems

**Process**:
1. Review existing research in `research/`
2. Propose research question in GitHub Discussions
3. Conduct research with documented methodology
4. Submit findings as markdown in `research/`
5. Include citations and reproducibility information

### 4. Literacy Application Testing

**Help test the self-narrative method**:
- Volunteer as tutor in pilot programs
- Provide feedback on learner experience
- Suggest improvements to dignity preservation
- Report edge cases or violations

**Process**:
1. Contact foundation@cyranoapp.org
2. Complete volunteer onboarding
3. Document experiences (anonymized)
4. Submit feedback through appropriate channels

## Contribution Standards

### All Contributions Must

✓ **Preserve dignity** - Never add features that could shame, harm, or violate agency

✓ **Maintain rigor** - Mathematical claims must be provable

✓ **Respect boundaries** - System describes, humans decide (no automatic collapse)

✓ **Include tests** - Code changes require test coverage

✓ **Document assumptions** - Make epistemic limits explicit

### All Contributions Must NOT

✗ **Oversell capability** - Don't claim certainty beyond what math proves

✗ **Hide limitations** - Acknowledge what the system cannot do

✗ **Bypass human authority** - Never automate collapse decisions

✗ **Introduce bias** - Maintain cultural neutrality in semantic processing

✗ **Compromise privacy** - Learner data must remain anonymized

## Review Process

### Pull Request Review

1. Automated tests must pass
2. Code review by maintainer
3. Documentation review if applicable
4. Discussion of mission alignment
5. Approval and merge or request for changes

**Review criteria**:
- Technical correctness
- Test coverage
- Documentation completeness
- Mission alignment
- No dignity violations

### Research Review

1. Methodology soundness
2. Mathematical rigor
3. Reproducibility
4. Alignment with existing framework
5. Acknowledgment of limitations
